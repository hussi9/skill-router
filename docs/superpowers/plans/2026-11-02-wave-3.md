# Wave 3 (reduced) — the router as an MCP server — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let any MCP client (Codex, Cursor, Gemini CLI, Claude Code) ask skill-router to route a task, find a skill, or read the audit — with Jev when a key is set, keyless otherwise.

**Architecture:** A dependency-free stdio MCP server (`mcp/server.py`, JSON-RPC 2.0 over newline-delimited stdin/stdout) exposing four read-only tools that call existing functions. No daemon: the feasibility spike showed it would save ~30–60 ms per hook against a ~400 ms Jev call, so `routerd` is dropped from this wave.

**Tech Stack:** Python 3.11+ stdlib only; pytest.

**Spec:** `docs/superpowers/specs/2026-11-02-skill-router-v3-vision.md` (R1, R6); retro `docs/superpowers/retros/2026-11-02-wave-4.md`.

## Global Constraints

- Read-only tools: no tool writes files, applies visibility plans, installs skills or runs the `/context` probe.
- `route` runs the router in non-hook mode (no pending state, no outcome or features logging, no holdout).
- Tool results carry skill names, reasons and numbers only; never prompt text echoed into logs.
- Jev used when `TYPESAFE_API_KEY` is available; keyless otherwise; the result says which.
- No auto-registration in any client config; `mcp/README.md` shows copy-paste snippets.
- Tests offline (Jev stubbed); suite-wide temp HOME and live guard apply.
- Commits intent-first, ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Malformed JSON-RPC line.** Expected: a JSON-RPC parse error response (-32700), server keeps running. Test: `test_malformed_line_keeps_server_alive`.
2. **Unknown tool or bad arguments.** Expected: `isError: true` tool result with one line, never a crash. Test: `test_unknown_tool_is_error_result`.
3. **Router prints to stdout.** Expected: nothing but JSON-RPC ever reaches stdout (router output captured). Test: `test_stdout_is_protocol_only`.

### Task M1: stdio MCP server

**Files:** Create `mcp/server.py`, `mcp/README.md`, `tests/test_mcp_server.py`; Modify `README.md` (one section), `CHANGELOG.md`.

**Interfaces:** Tools (JSON schema in `tools/list`):
- `route(task: str)` → `{"card": [skill...], "shortlist": [skill...], "path": str, "mode": "jev"|"keyless", "text": str}` (router output captured, `[skill-router]` lines kept as `text`).
- `find_skill(capability: str, limit: int = 5)` → installed matches (index ranking) + skills.sh cache matches (name, installs, audit, install command) — read-only, no network.
- `audit_skills()` → AuditReport summary (score, counts, top actions; no descriptions).
- `listing(project: str | None)` → cached `/context` measurement line for the project key, or "not measured".
Protocol: `initialize` (protocolVersion echoed from client or "2025-06-18", capabilities `{"tools": {}}`, serverInfo name `skill-router`, version from `VERSION`), `notifications/initialized` (no response), `tools/list`, `tools/call`, `ping`.
