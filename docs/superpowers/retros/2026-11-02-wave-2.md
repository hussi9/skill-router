2. **Tests reached the live `~/.claude` twice** (a session file in R3, the audit inputs in 2.3). Each was fixed by hand; nothing prevents the third.
3. **The gate was red for weeks** on machine state (pinned agents), which hid new failures. Now fixed with doctor's gate mode.
4. **Keyless overlap is uncalibrated.** Jaccard ≥ 0.6 was a guess; Jev's verdicts show it is far too loose.
5. **Still no live data.** Every Wave 1 measurement waits on the owner syncing the live copy.

## Correction found while verifying Wave 4's inputs (N3 applied)
Claude Code already budgets the skill listing: by default it uses 1% of the context window, caps each description at 1,536 characters (`skillListingMaxDescChars`), and when the listing overflows it drops descriptions of the least-used skills first, keeping names. So the audit's "~23.5k listing tokens" is the *uncapped* size, not what a session pays; the real cost is bounded by the budget, and the real damage is which descriptions get dropped. The skill listing in this very session shows it: most skills appear as bare names. Documented levers that do change the listing: per-project `enabledPlugins`, `skillOverrides` (`off` / `name-only` / `user-invocable-only`, not for plugin skills), `disable-model-invocation`, and the budget keys (`skillListingBudgetFraction`, `SLASH_COMMAND_TOOL_CHAR_BUDGET`). Hooks cannot edit the listing.

New now-fix **N4**: the audit reports the budget-capped listing and how many skills lose their description, instead of the raw sum.

## Next-wave decision
**Wave 4 (show Claude only what helps) moves ahead of Wave 3 (warm service + MCP).** Its goal is restated by the correction above: not "fewer tokens" (the harness already caps them) but "the right descriptions survive the cap" — the harness keeps the most-used, the router can keep the most relevant per project via `skillOverrides` (`name-only` for the irrelevant) and per-project `enabledPlugins`. That serves every user, keyed or not. Wave 3 is infrastructure whose value appears once more consumers exist. Wave 4 starts with research into which visibility levers Claude Code actually honours (N3 applied: verify the input before planning on it).
